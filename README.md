# Clean Spec: Specification Engineering for the Age of AI

A book about writing specifications that coding agents can compile into correct software.

> **Written by AI, for AI.** The manuscript, style guide, cover art, build pipeline, and CI in this repository were authored by Claude (Anthropic), working from Matteo Baccan's original outline and direction inside Claude Code, chapter by chapter. The book argues that a precise specification is what lets a coding agent produce reliable software — this project is that argument, demonstrated on itself.

## Read the book

Prebuilt copies live in `build/out/` and are kept current by a pre-commit hook (see [Building](#building)):

- [`clean-spec.pdf`](build/out/clean-spec.pdf) — print-ready, cover included
- [`clean-spec.epub`](build/out/clean-spec.epub) — e-reader format, cover included
- [`clean-spec.docx`](build/out/clean-spec.docx) — Word format
- [`clean-spec.md`](build/out/clean-spec.md) — the full manuscript concatenated into one Markdown file

## Layout

- `manuscript/` — the English manuscript, one file per chapter, plus `STYLE.md` and `OUTLINE.md`.
- `tools/check_manuscript.py` — lint script that enforces the chapter conventions.
- `build/build.ps1` — concatenates the chapters and renders EPUB/DOCX/PDF with Pandoc.
- `build/out/` — the built book (tracked in git; regenerated by the pre-commit hook and by CI).
- `.githooks/pre-commit` — rebuilds the book and stages `build/out/` before every commit.
- `assets/cover/` — the cover art: `cover.svg` (source, edit this one), `cover.png` (rendered, used as the cover image in EPUB and PDF), `cover.jpg` (alternate format).
- `docs/superpowers/` — design spec and implementation plan.

## Checking the manuscript

```powershell
python tools/check_manuscript.py            # all chapters
python tools/check_manuscript.py manuscript/07-three-levels-of-a-spec.md
```

## Building

```powershell
pwsh build/build.ps1                        # all formats Pandoc can produce
pwsh build/build.ps1 -Formats epub,docx
```

Requires [Pandoc](https://pandoc.org). PDF output also needs a LaTeX engine (MiKTeX or TeX Live) plus the DejaVu fonts (bundled with MiKTeX/TeX Live; `fonts-dejavu` on Debian/Ubuntu) so box-drawing diagrams and math symbols render correctly. Mermaid diagrams are kept as fenced code blocks; use a Pandoc Mermaid filter to render them as images. The build embeds `assets/cover/cover.png` automatically when the file exists — as the EPUB's cover image, and as a full-bleed first page in the PDF.

### Pre-commit hook

`build/out/` is committed, so it needs to stay in sync with `manuscript/`. Enable the hook once per clone:

```powershell
git config core.hooksPath .githooks
```

From then on, every `git commit` rebuilds the book and stages the refreshed files in `build/out/` automatically. If Pandoc isn't installed, the hook skips the build with a warning instead of blocking the commit; if the build tools are present and the build fails, the commit is aborted.

## Cover

Edit `assets/cover/cover.svg`, then re-render the raster copy used by the build:

```powershell
magick -background none -density 150 assets/cover/cover.svg assets/cover/cover.png
```
